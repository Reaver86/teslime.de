# First-party analytics

The shared backend and operational runbook live in the sibling ottoschuster.de
repository at `analytics/` and `docs/analytics.md`. Both sites use one database
and one German monthly report to alexander.schuster86@gmail.com and
otto.schuster@ottoschuster.de, generated by Otto’s job on the **1st of every month
at 08:00 Europe/Berlin**, covering the previous calendar month. Mobile usage is
shown as a percentage of page views, excluding tablets from the numerator;
zero traffic is labelled as unavailable. A separate daily cleanup retains events
for 90 days. Demo emails go only to Alexander.

Set `PUBLIC_ANALYTICS_ENABLED=true` only for an authorized production release
after the PHP 8.4 collector is installed. The default is disabled; previews must
leave it unset. `public/metrics/tracker.js` must match the canonical shared copy.
The public PHP loader reads private application/config files outside httpdocs.
Never include database credentials in the public build. Ordinary static deployment
must preserve the private backend, database and scheduler.

Teslime collects page views and explicitly marked business email/WhatsApp clicks.
The webmaster email is excluded. The privacy section in ContactFooter describes
first-party processing, daily pseudonymous visitor estimates, DNT/GPC and 90-day
retention. See the shared runbook for limits, recovery, tests and data definitions.
Run `npm run verify` and browser checks at 320/390/1440 before deployment.

No third-party tracking implementation is used. Only `/metrics/tracker.js` and
`/metrics/collect.php` are public. The shared PHP application and credentials
remain outside both document roots. Do not restore older tracking snippets or
the temporary private demo runner. Production deployment still follows deploy.md.
